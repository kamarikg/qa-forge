# QA Forge

[![CI](https://github.com/kamarikg/qa-forge/actions/workflows/ci.yml/badge.svg)](https://github.com/kamarikg/qa-forge/actions/workflows/ci.yml)

**QA Forge** is a hands-on QA Automation / SDET engineering project focused on testing a Go REST API with Python, PostgreSQL, Docker, and continuous integration.

The project demonstrates how backend development, automated API testing, database integration, and CI checks work together in a single testable system.

## Project Goals

- Build and test a REST API written in Go.
- Design a maintainable service and repository architecture.
- Automate API tests with Python and pytest.
- Verify CRUD operations, validation rules, HTTP status codes, and error responses.
- Test repository implementations against a shared contract.
- Run automated checks in GitHub Actions.
- Develop practical skills for QA Automation Engineer / SDET roles.

## Architecture

The Go API uses a layered design:

```text
HTTP Request
     |
     v
HTTP Handler
     |
     v
User Service
     |
     v
UserRepository interface
     |
     +-------------------+
     |                   |
     v                   v
  UserStore       PostgreSQLRepository
                         |
                         v
                     PostgreSQL
```

The repository interface separates business logic from data storage and allows different implementations to be tested against a common contract.

Python tests exercise the running API over HTTP rather than calling Go internals directly.

## API Endpoints

The service listens on `http://127.0.0.1:8080`.

| Method | Endpoint | Purpose |
| --- | --- | --- |
| GET | `/health/` | Health check |
| GET | `/version/` | API version |
| GET | `/users` | List users |
| POST | `/users` | Create a user |
| GET | `/users/{id}` | Retrieve a user |
| PUT | `/users/{id}` | Update a user |
| DELETE | `/users/{id}` | Delete a user |

The user API includes input validation and handling for invalid identifiers and missing users.

## Local Setup

### 1. Start PostgreSQL

From the repository root:

```bash
docker compose -f docker/postgres/docker-compose.yml up -d
docker compose -f docker/postgres/docker-compose.yml ps
```

The local container is configured with:

- Database: `qa_forge`
- User: `qa_forge`
- Password: `qa_forge`
- Port: `5432`

These are local development credentials. Do not reuse them for production.

### 2. Create the database table

The current project schema uses a `users` table. Initialize it once in the local database:

```bash
docker exec -i qa-forge-postgres psql \
  -U qa_forge -d qa_forge <<'SQL'
CREATE TABLE IF NOT EXISTS users (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name TEXT NOT NULL,
    email TEXT NOT NULL
);
SQL
```

### 3. Start the Go API

Open a terminal in the repository root and run:

```bash
cd go

DATABASE_URL='postgres://qa_forge:qa_forge@localhost:5432/qa_forge' \
  go run ./cmd/health
```

Keep this terminal running. The API listens on port `8080`.

In another terminal, verify the health endpoint:

```bash
curl -i http://127.0.0.1:8080/health/
```

Expected response: HTTP `200 OK` with a JSON health status.

### 4. Set up Python

From the repository root:

```bash
python -m venv .venv
source .venv/bin/activate

python -m pip install --upgrade pip
python -m pip install pytest requests
```

Run the Python tests while the Go API and PostgreSQL are running:

```bash
QA_FORGE_BASE_URL=http://127.0.0.1:8080 pytest -q
```

## Running Go Checks

From the repository root:

```bash
cd go

go test -count=1 ./...
go test -race -count=1 ./...
go vet ./...
go test -count=3 ./cmd/health -run TestUserRepositoryContract
```

These commands run the Go test suite, check for data races, perform static analysis, and repeat repository contract tests.

## Continuous Integration

GitHub Actions runs the project checks on pushes, pull requests, and manual workflow dispatches.

The workflow provisions PostgreSQL and then:

1. Installs Go and Python dependencies.
2. Prepares the test database schema.
3. Runs Go tests.
4. Runs the Go race detector and `go vet`.
5. Repeats repository contract tests.
6. Starts the Go API.
7. Runs the Python test suite against the API.

[View workflow runs](https://github.com/kamarikg/qa-forge/actions).

## Current Scope

Implemented foundations include:

- Go REST API health and version endpoints.
- User CRUD operations.
- Service and repository separation.
- In-memory and PostgreSQL repository implementations.
- Input validation and API error handling.
- Go unit and repository contract tests.
- Python API automation with pytest.
- PostgreSQL-backed GitHub Actions CI.

The project is evolving incrementally. Additional negative API testing, stronger test isolation, and expanded reporting can be added as the automation framework grows.
